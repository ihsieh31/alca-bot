# services/relay-worker

Alca Link relay on **Cloudflare Workers + one Durable Object** (P10). It runs the same `RelayHub` as the Node relay in `services/rendezvous` (pairing codes, mailboxes, ciphertext forwarding) plus the Google-account directory (`computers.list`, `connect`, `computer.register`) with the same token checks; the registry is kept in the object's storage as `acct:<HMAC(secret, sub)>` keys only.

- `wrangler.toml` — no secrets and no `[vars]` table (`keep_vars = true`, so a deploy keeps the dashboard's variables). `wrangler secret put ALCA_RELAY_SECRET`, set `GOOGLE_CLIENT_IDS` (Web + Desktop client IDs), `ALLOWED_ORIGINS` (the phone site; **required** for an official deployment) and `RELAY_MODE=production`, then `wrangler deploy`. `workers_dev = false` / `preview_urls = false`: the custom domain is the only endpoint (a self-hoster without one sets `workers_dev = true`). Steps: [docs/DEPLOY.md](../../docs/DEPLOY.md) § 2a.
- `/healthz` reports `ok:false` with a `warnings` list when the deployment is misconfigured: `GOOGLE_CLIENT_IDS` without `ALCA_RELAY_SECRET` (Google sign-in is off, and the account ops say why), or an empty `ALLOWED_ORIGINS` in production mode (browser sockets are then refused). Outside production mode an empty `ALLOWED_ORIGINS` is a loud warning only.
- **Webhook mailboxes** (`/v0/hooks/<id>`, connected-app triggers; review M3): the Node relay's protocol (`PUT` register with the token's SHA-256, `POST` deliver, `GET …/events?after=N` pull + ack), one Durable Object per mailbox id (`HOOKS` binding, class `HookObject`, migration `v2`), at most 500 events of 256 KiB each, kept a day; a mailbox idle for a week with nothing waiting deletes itself (alarm). Events are kept in Durable Object storage until pulled, readable by whoever runs the Cloudflare account.
- **One object for every relay socket** (pairing codes and the Google directory must meet in one place). It caps itself at `MAX_SOCKETS` (default 5000) and 32 sockets per address, and the hub closes a socket that says nothing for 10 s or is idle for 30 min and budgets each connection's bytes (review M2). Past a few thousand concurrent phones + computers this needs sharding by mailbox with a separate directory object for nameplates and accounts — not built.
- Not in this variant: serving the phone site (deploy it to Vercel), TLS options; Workers' 1 MiB message cap applies (the Node relay allows 4 MiB).
- Tests fake the runtime (`WebSocketPair`, storage, the `HOOKS` namespace): `test/worker.test.ts` runs the real Link host, enrollment and session through it and checks the import graph has no `node:` module; `test/hooks.test.ts` runs one webhook scenario against the Node relay and the Worker; `test/config.test.ts` the `/healthz` checks.
