# 關心時刻（Care moments）

> 狀態：第一版（`feat/care-moments`）。程式在 `packages/core/src/care/`、`packages/memory/src/life.ts`、`packages/store/src/repos/care-log.ts`（migration 32）；評測在 `packages/evals/src/care-*.ts`。

## 0. 為什麼要做

一個好的人類助理，會在對的時候說一句對的話。例子（已改寫成虛構情境）：使用者深夜結束一段很長的工作，說「剩下交給你，我要睡了，晚安」。好的回覆是：

> 好，剩下的我跑完測試再合併。晚安，後天的鋼琴檢定加油。

它做對了四件事：

1. **記得**一件和工作無關、但對他重要、有日期的事（兩天後的檢定）。
2. **察覺時機**：快午夜、他自己說要走了、這段工作已經收尾。
3. **選擇他的利益而不是對話**：不追問、不再提新工作，讓他去睡。
4. **只說一句，不說從哪裡知道的**。

這份文件說明 Alca 怎麼把這件事做成一條**管線**，而不只是一段提示詞。提示詞做不到「克制」：模型看到記憶，就會想用；看到「可以關心使用者」，就會每輪都關心。所以「要不要說」由程式決定，模型只負責「怎麼說好那一句」。

## 1. 原則（依重要性）

1. **克制是預設。** 預設是「什麼都不加」。只有一個確定性的閘門全部通過時，模型才會看到可以說的那一件事；其他每一輪，連提示都不會出現。寧可錯過一次，也不要多說一次。
2. **時機比內容重要。** 對的時刻只有兩種：使用者要離開（晚安、先這樣、bye），或一件事自然結束（他婉拒了最後一個提議、說「這樣就好」）。進行中的工作、快速問題、白天的「好」「ok」都不是。
3. **他的利益優先於延長對話。** 要走的人：確認已處理的事、道別；不問問題、不提新建議或新工作。
4. **最多一句，一件事。** 一則回覆最多一句關心；同一個對話同一天最多一次；同一件事 24 小時內在任何對話都不重提。
5. **不說來源，不編造。** 不說「我記得你說過」「你的行事曆上寫」；只提時間軸上真的有的事。
6. **沉重的話題只給同理。** 有人過世、住院、分手時，不會出現任何「加油」；醫療相關的行程永遠不當成關心的話題。
7. **使用者說了算。** 「別再提這種」「不用關心我」會變成他自己的固定規則，之後不再出現。
8. **跟著使用者的語言。** 中文訊息用中文，英文訊息用英文。

## 2. 管線

```
使用者訊息
   │
   ├─(1) 擷取  回合結束後：有日期的生活事件 → life: 記憶（絕對日期＋時區）；取消／延期
   │
   ├─(2) 情境  每輪、確定性：當地時間、是否在道別、工作階段長度、工作狀態、情緒重量、語言
   │
   ├─(3) 決策  硬閘門 → 打分 → 最多選一件（或休息，或什麼都不選）＋固定的理由字
   │
   ├─(4) 受限生成  只有決策說「可以」時，<alca:moment> 才進入這一輪的情境，且只放被選中的那一件
   │
   ├─(5) 事後檢查  回覆寫完後由程式檢查：多的關心、沒被選中的事、說來源、道別後的問題或提議 → 刪句
   │
   └─(6) 回饋  下一則訊息就是反應（感謝／忽略／別提）→ 類別權重、抑制規則、精確率
```

### 2.1 擷取：生活時間軸（`@alca/memory` `life.ts`）

- 句子裡有「類別詞」＋「可解析的日期」才算事件：考試／檢定（exam）、比賽（contest）、面試（interview）、旅行／班機（trip）、生日（birthday）、上台發表（performance）、典禮（ceremony）、醫療（medical）。
- **日期在聽到的當下就換算成絕對日期**，用使用者的時區：「後天下午兩點半」在 3/10 說，存成 `2027-03-12 14:30, Asia/Taipei`，之後不會因為「後天」而過期。支援中文數字時間（一點半、十點十五分）、`13:30`、`9am`、月日、星期幾、`on Friday`。
- 存成一則 `fact` 記憶：`subject = life:<類別>:<名稱>`、`body = 名稱 (日期 時間, 時區)`、`due_at = 開始時刻`（沒有時間就是當地 23:59）。它和偏好分開；來源（哪個對話、哪則訊息）由記憶本身記錄；「什麼時候被提過」記在 care log。
- **不是事件**：問句、願望／假設（希望、如果）、已經發生的（考完了、已經）、截止日（交報告、繳費——那是主動留意的工作，維持原本的 `due:` 記憶）。
- **延期**（「延期到 3/25」）是同一個 subject 的新版本，取代舊的；**取消**（「取消了」「不去了」）會寫一則沒有日期的「（已取消）」新版本，事件因此離開時間軸。使用者說「忘記…」照記憶原本的規則永久刪除。
- **看得到、改得了、刪得掉**：事件就是一般的記憶，記憶頁面會列出來（`鋼琴檢定 (2027-03-12 14:30, Asia/Taipei)`）。在記憶頁面改日期，`due_at` 跟著本文重新計算；改成沒有日期的文字，事件就離開時間軸；忘記它，時間軸也不會再有它。
- **記憶模式**：記憶關閉時，時間軸是空的、不會有任何一句，回饋也不寫任何記憶（「別再提醒我」的規則、取消註記都不寫）；「只用自己的筆記」時只讀這個 bot 自己的事件，不讀共用的使用者模型。

### 2.2 情境模型（`care/situation.ts`）

純函式，輸入相同就輸出相同：

| 欄位                  | 怎麼判斷                                                                                                                         |
| --------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `hour`、`night`       | 使用者時區的當地時間；22:00–04:59 算夜晚                                                                                         |
| `closing`             | `sleep`（我要睡了、晚安、going to bed）或 `bye`（訊息**結尾**是先這樣、掰、talk tomorrow）；「先這樣做，然後…」不算              |
| `endOfExchange`       | 助理剛講完，使用者短短回「不用」「這樣就好」，或把提議延後（「晚上再試」）。單純的「好」「ok」不算（在提議後面那是「好，去做」） |
| `lingering`           | 一小時內說過要睡，深夜還在                                                                                                       |
| `question`、`midTask` | 有問句、有工作請求、或有等批准的工作                                                                                             |
| `sessionMinutes`      | 往回找，訊息間隔 < 45 分鐘的這一段有多長                                                                                         |
| `heavy`               | 這則或最近 6 則使用者訊息有過世、住院、分手等                                                                                    |
| `lang`                | 有漢字是中文，否則英文；都沒有用 bot 的語言                                                                                      |

### 2.3 決策（`care/policy.ts`）

**硬閘門**（任一個不過就安靜，並記下理由）：

| 順序 | 閘門                                              | 理由字                                 |
| ---- | ------------------------------------------------- | -------------------------------------- |
| 1    | 不是道別、不是自然結束、也不是睡前還在 → 不是時刻 | `not-a-moment`（不記錄，也沒有 block） |
| 2    | 記憶關閉                                          | `memory-off`                           |
| 3    | 沉重話題                                          | `heavy`                                |
| 4    | 使用者要求過不要關心                              | `suppressed`                           |
| 5    | 道別但還在問問題（先回答）                        | `question-pending`                     |
| 6    | 本對話 18 小時內已說過同類的一句                  | `thread-cooldown`                      |

**單件事的判定**（每件事各有一個結果，寫進 `scored`）：已過（`past`；沒說時間的「今天」過了中午也算）、超過 72 小時（`too-far`）、使用者要求不提這類（`suppressed`）、本對話已經有人提過（`already-mentioned`）、24 小時內在任何對話被助理提過（`recently-mentioned`）、醫療（`heavy-item`）、分數不夠（`below-threshold`）。

**分數**：

```
score = 重要度(類別) × 接近度(差幾天) × 時刻契合度 × 回饋權重
重要度：考試／比賽／面試 1；旅行／上台 0.8；生日 0.7；典禮 0.6；截止日 0.4；醫療 0
接近度：今天 1、明天 1、後天 0.85、大後天 0.6（仍須在 72 小時內）
契合度：深夜道別 1、白天道別 0.9、自然結束 0.7
回饋權重：每次正面 +0.1、忽略 −0.1、反感 −0.3，限制在 [0.5, 1.2]
門檻：0.5
```

結果最多選一件（分數最高者，其他是 `runner-up`）。沒有事件、但深夜而且他說要睡 → 可以選「休息」（同一對話一次）。都沒有 → 道別時給「只是收尾」的規則，否則什麼都不給。每個時刻都寫一列 `decision` 到 care log（理由字、分數、類別，**沒有內容**）。

### 2.4 受限生成（`care/block.ts`）

只有決策是 `event`／`rest`／`closing` 時，這一輪的情境（volatile 層）才多一個 `<alca:moment>` 區塊，穩定的系統提示完全不變（prompt cache 不受影響）。區塊只有：

- 時刻：當地時間、他要去睡／要離開、這次聊了多久；
- 被選中的**那一件**（名稱、用他的說法講的日子「後天（3/12 週五） 14:30」），或「休息」；永遠不放整個時間軸、不放記憶編號；
- 兩條規則（`CARE_RULES`，納入 `check:prompt-budget` 的 `rules.care.*`）：收尾的規則，和「只有真的自然才加一句……不合適就什麼都不加」。

### 2.5 事後檢查（`care/post-check.ts`）

模型回完之後，由程式只做「刪句」，不加字，也不會刪到空：

- 提到**沒被選中**的時間軸事件 → 刪；例外：那件事在這個對話稍早已經談過，回覆只是平鋪直敘地交代（「札幌旅行的訂房確認信寄出了」），那是「確認處理好的事」，保留；祝福、提醒（別忘了、記得）、休息或說來源的句子照樣刪；
- 第二句關心 → 刪；
- 關心的那句說了來源（我記得你說過、from your calendar）→ 刪；
- 使用者在道別、睡前還在或剛婉拒：回覆最後兩句（空行不算）裡的問題或新提議 → 刪。「要我」只有在問句裡才算提議：「你要我改的都改好了」是交代，保留；「不需要我再動」也是；
- 不是時刻的一般回合：回答裡提到事件沒關係（他問了「這週忙什麼」），但沒來由的祝福（「明天考試加油！」）會被刪；
- 使用者自己在這則訊息提到的事，不算「沒被選中」。
- 切句：在 。！？!? 之後（「！？」連在一起、後面的 」』）" 跟著前一句）、換行之後、「. 」「; 」之後切；三個反引號的程式碼區塊是一整塊，不切也不刪。切開的句子接回去一定等於原文，所以刪句不會弄壞標點或留下落單的 」。

改過的回覆會更新已存的訊息並發出 `reply.revised`（`issues` 是 `care:<原因>`）。它排在「回覆檢查」附加元件之前，所以後者看到的是修過的文字。

### 2.6 回饋（`care/feedback.ts`、`care/service.ts`）

- 一句關心真的出現在回覆裡，就記一列 `shown`；助理回覆提到時間軸上的事，記一列 `mention`（跨對話 24 小時不重提就是看這個）。
- 同一對話的下一則訊息是反應：謝謝／你也是／晚安 → `positive`；「別再提這種」「stop reminding me」→ `negative`，並寫下使用者自己的規則（`suppress:care:<類別>`，或 `suppress:care` 全部關閉）；其他 → `ignored`；12 小時沒有下一則也算忽略。
- 「不用關心我」「別再叫我去睡」不需要先有一句關心，直接成為規則。回覆會簡短告訴他「已記下」。
- 權重回到 2.3 的分數；`CareMoments.metrics(botId)` 給出最近 30 天的時刻數、出現數、正面／反感／忽略、精確率（正面 ÷ 有反應的）、安靜的理由分布。
- care log 只存編號、類別、理由字和數字，保留 90 天；刪除對話會一併刪掉它的列。

## 3. 護欄一覽

| 護欄                                       | 在哪裡                                                 |
| ------------------------------------------ | ------------------------------------------------------ |
| 一則最多一句、一件事                       | 決策只選一件；事後檢查刪第二句                         |
| 同一對話同一天最多一次（事件、休息各一次） | `thread-cooldown`（18 小時）                           |
| 同一件事 24 小時內不在別的對話重提         | `recently-mentioned`（care log 的 `shown`／`mention`） |
| 本對話已經講過就不再講                     | `already-mentioned`（掃描對話內容）                    |
| 進行中、快速問題、白天的「好」             | 不是時刻，連 block 都沒有                              |
| 沉重話題、醫療行程                         | `heavy`、`heavy-item`                                  |
| 使用者說不要                               | `suppress:care*` 規則，`suppressed`                    |
| 不編造、不說來源                           | 只放被選中的真實事件；事後檢查刪來源句與沒被選中的事   |
| 不把要走的人拉回工作                       | 收尾規則；事後檢查刪結尾的問題與提議                   |

## 4. 從真實對話學到的門檻（彙總，不含任何個人內容）

資料：一個月的真實對話紀錄（約 700 個「使用者訊息＋助理回覆」）。分析在工作區外以腳本完成（時刻種類用和 2.2 相同思路的規則粗分類，數字是近似值），下面只列彙總數字；所有評測案例都是虛構改寫，沒有任何真實姓名、學校、地址、日期或訊息原文進入 repo。

**助理主動帶出一件有日期的個人事件：5 次（約 0.7%）。** 那位助理本身就很克制。

| 情境                                              | 次數 | 有說事件 | 觀察                                                                                                 |
| ------------------------------------------------- | ---- | -------- | ---------------------------------------------------------------------------------------------------- |
| 深夜說要睡，事件在 3 天內                         | 4    | 1        | 唯一說了的那次被使用者明確稱讚；另外 3 次沉默（其中 1 次那件事在同一對話已經聊過、1 次前一天已說過） |
| 白天婉拒提議，事件在 3 天內                       | 7    | 2        | 1 次是對話本來就在談那件事；1 次同一句話約 4 小時前已在另一個對話說過（重複）                        |
| 白天的「好」「ok」，事件在 3 天內                 | 15   | 0        | → 單純確認不是時刻                                                                                   |
| 深夜的快速問題（例如「還要多久」），事件在 3 天內 | 10   | 0        | 有 2 次在「說過晚安還在聊」時加了一句叫他去睡 → `lingering` 只給休息                                 |
| 深夜的工作請求，事件在 3 天內                     | 29   | 0        | → 進行中不是時刻                                                                                     |
| 白天的問題與工作，事件在 3 天內                   | 251  | 1        | 那 1 次是延後提議（「晚上再試」）之後 → `endOfExchange` 含延後                                       |
| 道別後回覆以問題結尾                              | 1    | —        | 「要我幾點提醒你嗎？」→ 事後檢查會刪                                                                 |

推得的設定：

- **時窗 72 小時、接近度遞減**：被說出口的事件都在 1–3 天內；被稱讚的那次是 2 天。
- **跨對話 24 小時不重提**：唯一的重複就發生在約 4 小時內的兩個對話。
- **「好」「ok」不算時刻、婉拒與延後算（但分數較低 0.7）**：15 次確認沒有一次適合；婉拒有 2/7 說了。
- **問題與工作請求不是時刻**：261 次深夜／白天的問題與請求中只有 0–1 次說了。
- **睡前還在只給休息**：真實紀錄中這時說「快去睡吧」最被肯定，但同一件事沒有再提。

和真實紀錄不同的地方（刻意的）：深夜說要睡、事件在 1–2 天內、而且沒有被提過時，Alca 會說那一句（真實紀錄 4 次中說了 1 次）；但同一天之後的其他對話就不會再說（真實紀錄在隔天早上與中午各說了一次）。總量一樣或更少，但落在最對的那一刻。

- **語料庫**（`packages/evals/src/care-cases.ts`，`pnpm evals --filter care`，以及 vitest `care-corpus.test.ts`）：7 個應該說的案例、17 個不該說的案例（工作中、快速問題、白天確認、對話內已提、別處已說、第二次道別、沉重、抑制、太遠、醫療、道別帶問題、今天已過、英文工作中……），各跑兩種模式：
  - `obedient`：模型照區塊做；
  - `tempted`：模型每次最後都硬加「〇〇加油！要我明天提醒你嗎？」——閘門與事後檢查仍須做到 **0 句誤報**。
  - 門檻：召回率 1、誤報 0（兩種模式）。
- **真模型評測**（`pnpm evals:live`，手動、不在 CI）：`care.midnight-goodbye`、`care.no-block-mid-task`、`care.closing-only`、`care.english-goodnight`，由評審模型依規則打分。
- **上線後**：看 `CareMoments.metrics(botId)` 的精確率與安靜理由分布；精確率下降或 `negative` 增加時，先收緊門檻或類別重要度，而不是改提示詞。

## 7. 已知限制與後續

- 擷取是規則式：說法太自由（「那個比賽改到下下週」）可能抓不到；之後可接模型擷取器，但輸出格式不變。
- 名稱比對用字元雙字組；同一件事換了說法（全名與簡稱）可能被當成兩件事。
- 「自然結束」只看最後兩則訊息；長時間沉默後的離開（沒有說再見）偵測不到，這是刻意的保守。
- 指標還沒有出現在設定畫面；目前由 `metrics()` 提供。
- 第二次「晚安」時的休息句允許一次；更細的「已經說過晚安」語氣控制留給模型。
